## 2. 26 项能力在本代的用途

玩家操控仍然需要能力差异：直接影响移动 / 触球 / 对抗的能力决定手感；无球、决断等影响另外五名队友及对手 AI。因此完整保留 26 项，展示层可分组，不应因“手动比赛”而删除 AI 需要的字段。

下表描述当前主要消费位置；不代表每项属性在每帧、每个动作中都有独立线性加成。

| 字段 | 含义 | 当前主要用途 |
| --- | --- | --- |
| pace | 速度 | 基础最高速度、跑动风格与突破 |
| acceleration | 加速 | 起步加速、响应、跑动偏好 |

### 保留但不能夸大为完整机制的字段

- 总评 / 等级 / 球员池主要用于资料和组织，不是每次触球按总评抽胜负。
- 惯用脚已参与动画左右表现；尚未完成每一种传射的弱脚精度 / 力量系统。
- 逆足、花式星级主要展示，未完整驱动弱脚惩罚或技巧解锁。
- 前作 traits、state、升级 / 参考能力完整保留，但不是把两代模拟引擎的全部特性效果直接搬入本代。
- 国籍、肤色、头发、脸型和姓名不作为能力加成来源。

## 3. 模型与体型

当前使用连续蒙皮人体、骨骼和程序动作，默认穿足球服，服装自定义仅预留未来方向。67 名传奇按稳定 ID 维护身高、肩宽、躯干深度、髋部、腿长、肤色、脸部与毛发等差异；并非 67 套完全独立手工拓扑。

配置在 [legend_appearances.json](../space-football-demo/assets/humanoid/legend_appearances.json)，来源与验证见 [LEGEND_MODELS.md](LEGEND_MODELS.md)。67 人范围按传奇标志或历史 `legend-` ID 判定，其中包含一张虚构角色卡；身高取自球员库，其他比例和外观是参照卡画的制作近似，不是人体扫描数据。展厅由根目录 `Start-Legend-Models.cmd` 启动，共 17 页，每页最多四人，支持观察、转向、跑动和近看。其他球员仍利用身高与基础人体参数形成差异，没有逐人精修全库。

### 身体如何影响手感

身高先影响实际人体比例、空中接触高度、门将范围和动画。新增身体比例修正以有限幅度参与运动和对抗，避免高壮球员笨重到无法操作，或瘦小球员在所有方面都占优。

| 参数 | 设计范围 |
| --- | --- |
| 加速系数 | 0.92–1.08 |
| 刹车系数 | 0.90–1.10 |
| 转身时间系数 | 0.90–1.10，最终仍受全局上下限约束 |
| 跑动转向系数 | 0.89–1.00 |
| 护球修正 | -0.07 至 +0.085 |
| 对抗稳定性 | 0.90–1.12 |
| 接触相对质量 | 0.84–1.20，不是公斤体重 |
| 身体碰撞范围 | 约 ±3.5% |
| 脚部触及 | 约 ±2.5% |
| 抢断伸脚 | 约 -6.5% 至 +7% |
| 趟球步幅 | 约 ±3.5% |

具体参与量由身高、肩 / 躯干 / 髋部和腿比例计算，不给某个名字硬编码“更强”。最高跑速和原始属性保持原本计算，体型主要改变启动、停止、变向、接触与护球感。旧的身高 / 力量转身惩罚已被替换，不应再次叠加。

全库都可获得基础体型机制；传奇多了逐人比例输入。颜色 / 毛发变化不会改变这些系数。服务器和客户端预测共用 [player_physique.gd](../space-football-demo/player_physique.gd) 与 [player_movement.gd](../space-football-demo/player_movement.gd)，详见 [PHYSIQUE_GAMEPLAY.md](PHYSIQUE_GAMEPLAY.md)。

## 5. 维护与联机兼容

1. 修改球员应以稳定 ID 为主，不按显示姓名或数组位置推测身份。
2. 保留原始快照、清单、资源来源和许可；导入脚本是维护工具，不是启动依赖。
3. 当前网络以数值索引传球员身份，并有 386 条范围约束；变更数量、顺序或能力时要同步检查协议、编解码和两端内容一致性。现有协议号不等于球员库哈希认证。
4. 新增体型机制要覆盖渲染、碰撞、移动、快照恢复和预测；新发型通常只应影响外观。
5. 人体相关 CC0 许可不自动覆盖球员卡画、字体或整个游戏。项目现为公开开发仓库，保留各资源自己的来源记录和许可；未新增覆盖整个项目的开源许可证。
