# 当前状态与开发边界

更新：2026-10-06。快速比赛的球场、天气、低重力及两轮[架构重构](ARCHITECTURE_REFACTOR.md)已纳入提交 `20b1921` 并推送，当前协议 7。仓库已由用户改为公开，已通过 GitHub API 核对；未打包或部署。

## 已确定的产品方向

- 以类似 FIFA 的直接操控足球为基础，当前 **6 对 6：1 门将 + 5 外场**。联机是 **1 对 1，每人控制一队**，可切换球员。
- 星际主题体现在场景、界面、球员视觉及可选规则。主线操作仍是足球；身体差异可以适度明显，但不能造成冗长转身或失控。
- 电脑客户端优先，键盘和 Xbox 手柄都要完整支持比赛及菜单；按键提示放在按钮内部，随设备切换。
- 原生设计分辨率 2560×1440。安卓仅保留接口，成熟后再做触屏、设备测试和打包。当前也不急于打包 Windows。
- 主力玩家在中国大陆，计划使用阿里云香港服务器。已有网站及 Rougelite 服务继续运行，YFFM3 另设计算服务；尚未实际部署。

## 已知缺口与待验证项

1. **公网与容量未知。** 未登录阿里云主机，CPU、内存、带宽和现有 Rougelite 负载未知。Linux 导入 / 安装 / 长稳、三网 RTT、拥塞和断线需灰度验证。一场一个进程，尚无多房间调度、生产票据、账号接入或断线续赛。
2. **网络预测有范围。** 立即呈现本方移动和动作，但不预测成功抢断、比分或完整世界回滚；快照超过 300 ms 时停用预测，断线不会自动恢复整场。双方必须使用同版程序与球员库，当前没有完整资源哈希握手。
3. **规则是六人制产品规则。** 不是对某项真实赛事规则的完整复刻。普通模式与室内附加选项存在区别；边线球 / 角球 / 球门球的 4 秒执行限制已在基础逻辑中，不能笼统写成“所有 4 秒规则默认关闭”。
4. **手感仍需人工迭代。** 程序骨骼动画已覆盖多种动作，没有高质量动捕整套动画；跑动、触球、射门高度、镜头冲击和不同体型仍需真实操作体验。手柄图标适配不等于各品牌实机全部验证。
5. **数据存在未落地字段。** 逆足 / 花式星级部分缺失，当前主要展示；惯用脚参与动作表现，尚不能称为完整弱脚误差系统。前作特性、升级和状态字段保留，不代表原代机制逐项移植。
6. **模型覆盖范围。** 67 名传奇有逐人配置，其余球员采用共用人体和基础差异；足球服装固定基础方案，未完成服装自定义系统。没有为全库逐人精修肖像级模型。
7. **局部尺度需复查。** 静态审阅发现 `match_sim.gd` 的传球目标仍有约 `x ±30 / y ±16.5` 限制，球场已扩为约 `±35.05 / ±19.72`。这是后续应验证的尺度一致性问题，未在本次实测确认为错误，也未改动。
8. **其他边界。** 没有点球大战；当前不是标准上下半场流程。替补由程序补齐，尚无完整赛前替补名单编辑。训练主要影响战役速度，没有完整球员养成 / 转会 / 抽卡经济。安卓触屏与打包均未落地。

## 建议接续顺序

1. 同版本灰度先开一场独立 UDP 服务，观察 Rougelite 与 YFFM3 同时负载，采集大陆玩家 RTT、抖动和纠正指标。
2. 按实测调整输入 / 快照缓冲和异常网络体验；补入场票据、会话恢复，再扩多房间。不要凭本机测试宣称“低延迟已解决”。
3. 人工体验普通 / 冰球模式下的短传接应、边界争抢、门将覆盖、高球、身体差异、犯规与重启球；优先核对扩容后所有目标 / 站位范围。
4. 收敛现有机制，明确默认辅助与规则；再考虑更深入的弱脚、射门特性、战术编辑和星际场地变体。风格化机制应独立开关，保持基础对战可比较。
5. PC 流程稳定后，接安卓输入提供器、触控布局、性能档位及真机验证。

以上是排序建议，不代表本次已开始实现这些功能。
