# 游戏机制总览

核对日期：2026-10-04。依据当前源码整理；这是实现说明，不是所有功能均已完成真实玩家体验验收的声明。键位见 [CONTROLS.md](CONTROLS.md)，球员参数见 [PLAYER_DATA.md](PLAYER_DATA.md)，测试范围见 [VERIFICATION.md](VERIFICATION.md)。

## 1. 比赛基础

| 项目 | 当前机制 |
| --- | --- |
| 队伍 | 每队 6 人，合计 12 人；1 名门将、5 名外场 |
| 固定槽位 | 0 门将、1 中锋、2 右翼、3 左翼、4 后卫、5 中场；球员主位置可以与槽位名称不同 |
| 操控 | 一人控制整队，可自动 / 手动 / 定向切人；其余队员由 AI 驱动 |
| 球场 | 原面积增加 20%，长宽分别乘 √1.2；约 70.11 × 39.44 游戏单位 |
| 球门 | 宽 10、高 3.6、深 3 游戏单位；场地扩容时球门和球员没有同比放大 |
| 时间 | 本地快速比赛、冰球、战役每场和联机统一为 300 秒（5 分钟）有效比赛时间；自动化测试可显式覆盖 |
| 平局 | 常规结束平局进入 30 秒金球加时；仍无胜负允许平局，没有点球大战 |
| 暂停计时 | 捡球、摆球、犯规、进球演出等阶段不增加有效比赛时间；无标准上下半场交换 |

2026-10-06：比赛画面移除了测试用的逐动作文字播报、球员姓名后的持球 / 接应 / 取球状态、头顶协防 / 跑位文字及动作恢复说明。保留姓名 / 号码 / 黄牌、比赛规则与结果、操作按键提示、蓄力条和原有音效；模拟事件本身仍供内部诊断使用。

这里的尺寸是代码坐标，不要直接写成真实米。人体使用约 1.45 游戏单位 / 米，规则中的 5 米退距另做了换算。

比赛主阶段为进行中、重启球、犯规处理、进球，结束另有标记。金球进球也先完成进球阶段再结束。来源：[队伍](../space-football-demo/team_config.gd)、[场地](../space-football-demo/pitch_geometry.gd)、[模拟](../space-football-demo/match_sim.gd)。

## 2. 模式、阵容与战役

### 快速比赛

面向开发测试，默认玩家对 AI。随机种子决定双方阵容，两队合计十二人不重复，优先主位置、其次适配位置，不是任意抽六个人。槽位候选为：

| 槽位 | 候选主位置 |
| --- | --- |
| 门将 | GK |
| 中锋 | ST |
| 右翼 | RW / RM / AM |
| 左翼 | LW / LM / AM |
| 后卫 | CB / DM / RB / LB |
| 中场 | AM / DM / CM；当前库中没有主位置 CM 的记录 |

支持原阵容重赛和重新随机。使用竞争模式参数，不读取战役训练加成，不扣训练费用，不发战役奖励，也不覆盖手工首发队伍。来源：[quick_match.gd](../space-football-demo/quick_match.gd)。

### 冰球模式

快速比赛的开赛界面另有球场、天气和重力选项，可与普通/冰球规则自由组合；大风偏移空中球，暴雨改变抓地力与球的地面阻力，55% 低重力影响足球和跳跃。银河流星与雷雨中的间歇闪电属于视觉效果。完整参数见 [环境机制](MATCH_ENVIRONMENT.md)。

仍是足球运动和足球球员，改变的是球场边界。边线 / 底线碰球后反弹，不产生常规出界；门洞仍可进球，犯规等其他判罚仍可发生。边界两轴速度分量分别约乘 -0.78 / -0.82，反弹损失能量。AI 自由球追逐范围单独处理墙边和角落，避免队形约束阻止追球。

冰球模式与战役的星际规则开关是不同配置，不能把冰球理解成自动开启全部星际加成。

### 三站战役

| 站点 | 对手 | 基础强度参数 | 获胜奖励 | 开启星际规则后的场地特性 |
| --- | --- | --- | --- | --- |
| 澜星·潮汐初航 | 澜星探索者 | 0.82 | 420 星币 | 边界反弹 |
| 余烬·恒星风暴 | 余烬日冕队 | 0.96 | 580 星币 | 每 18 秒中有 6 秒太阳风影响自由球 |
| 卡西尼·群星之巅 | 卡西尼卫冕者 | 1.08 | 900 星币 | 出球速度提高 15% |

经典规则不会因为场景名称自动获得以上特性。代码中星际规则（`arcade`）各站都启用边界反弹，后两站再叠加风 / 出球速度特性；该模式也跳过部分常规抢断犯规判定。冰球模式仅独立开启反弹，不等于这个开关。难度在对手强度参数上调整，不能据此断言 AI 使用额外跑速作弊。战役胜利推进航线；非胜利结算 100 星币，主动放弃不结算胜利奖励。初始 360 星币，记录场次、胜场、进球。

五个外场位置各最多训练 5 次，费用为 `180 + 当前等级 × 140`。当前训练主要增加战役移动速度，每级 `0.12 × 0.78`；门将专项一次 500 星币，速度增加 `0.5 × 0.78`。旧函数名仍是 `recruit()`，实际不应写成完整签约 / 转会系统。训练按位置保存，不是每个球员 ID 独立成长。来源：[campaign.gd](../space-football-demo/campaign.gd)。

### 手工球队与替补

球员库可查看卡画、资料、能力和模型，并配置首发。手工阵容验证要求六个不同 ID、首位门将、其余非门将；不像快速比赛那样强制每个外场槽的主位置匹配。默认队伍及旧五人存档迁移见 PLAYER_DATA。

替补由程序按角色补齐四人，通常覆盖 GK / ST / RW / CB，并排除首发 ID。比赛菜单可选择下场和替补，门将与门将互换，申请在后续死球执行；不是随时瞬间替换。黄牌、疲劳等状态按换人逻辑保留，短时体力重新初始化；换人版本供联机防止旧动作落到新球员上。尚未提供完整的赛前替补名单编辑器。

## 3. 移动、转向与持球

- 键盘八方向且对角线归一化，摇杆支持连续角度与力度；摇杆死区约 0.18。球员不会因为斜走获得 √2 倍速度。
- 全局速度系数 0.78，基础速度约为 `(5.8 + pace / 99 × 2.9) × 0.78`，冲刺倍率 1.42。加速、刹车、侧向惯性、反向先减速、持球损耗共同决定实际速度。
- 转身按方向差、灵活、加速和盘带连续执行。180° 转身标定在体型修正后限制于约 0.224–0.352 秒，跑动转向约束还会影响实际完成时间；不是每次按方向都强制锁住相同时间。人物朝向、速度方向与动作释放有关联。
- 短时体力影响冲刺和恢复，耐力影响消耗 / 恢复率。长期疲劳另存，最高约 0.65，并影响速度；体力条恢复不等于疲劳完全消失。
- 持球使用脚边触球、控球误差与步态节奏，支持护球、技能转向、冲刺大步趟球。先触球 / 出脚再改变球路，避免按键帧与动作完全脱节。
- 玩家和 AI 共用移动计算，AI 不应额外获得追球加速。身体挤压按相对质量分配小幅位置修正，有上限，不直接向足球叠加任意推力。

动作表现根据实际渲染位移计算步幅、步频，手臂与腿交替协调，有起步、刹车和转向倾斜。球员顶部倒三角是当前操作标记，已移除脚下控制圆圈。来源：[player_movement.gd](../space-football-demo/player_movement.gd)、[locomotion.gd](../space-football-demo/locomotion.gd)、[skinned_player.gd](../space-football-demo/skinned_player.gd)。

## 4. 传球、接球与配合

有短传、直塞、高空直塞、传中、低平传中、大力短传、二过一。按住传球增加力度，基础参数约 `clamp(0.28 + 按住毫秒 / 800, 0.28, 1)`；短传类约 0.07 秒出脚准备后释放。传球会受方向、能力、目标位置、跑动和线路压力影响，球实际飞行，不保证必到脚下。

直塞瞄准队友前方空间，参考推进方向和队友速度；高球越过低处拦截，但存在身体高度、跳跃和门将威胁。二过一会让原传球人继续前插约 2 秒；还可单独请求队友前插或靠近接应。

辅助从较窄到较宽选择候选目标，方向锥约 15° / 38° / 65°，角度修正比例约 0.25 / 0.75 / 1。自动切人开启时，会转到选定接球人；接球辅助预测来球位置和惯性，让接球人主动靠近可接点，即便有移动输入也可有限度协助。标准 / 高接球档约 50% / 85% 混合、约 1.4 / 2.8 秒窗口；明显反向操作、手动换人、取消等会退出或让出控制。

辅助不应提供瞬移、额外最高跑速或无限接球距离。附近低速自由球还有小范围无方向输入的接近协助；得球后不应继续自动带跑。可选脚边小方向指示器用于理解出球方向，不替代顶部选人标记。

预输入允许合适的接球场景在得球前短时间登记下一脚传球 / 射门，窗口约 0.4 秒；失去资格、切人、阶段变化会清理，避免旧命令突然触发。来源：[play_assistance.gd](../space-football-demo/play_assistance.gd)、[match_mechanics.gd](../space-football-demo/match_mechanics.gd)。

## 5. 射门与空中争夺

射门是按下开始蓄力、松开出脚。普通本地蓄力起始约 0.1、每秒增加 0.9，约一秒到满；联机按输入帧计算时长，避免网络到达间隔放大力量。出脚准备约 `0.035 + 0.025 × 蓄力` 秒。

- 普通射门：力度影响速度、高度与射门表现。高蓄力不保证更好，可能高出横梁；大力射门使用相应身体动作。
- 搓射：增加旋转和弧线取向；挑射：抬高球路，以越过门将为目的，速度和轨迹不同。
- 假射：蓄力期间按传球取消真正射门并播放假动作。
- 头球 / 凌空：按来球高度与球员可达高度选择空中动作，起跳能力和身体高度参与；不能在任意高处自动触球。
- 头球传球 / 解围：按对应传球或高球动作，在适合高度处理。尚未实现完整的手动胸部停球控制方案。

射门辅助调整目标与误差，仍受门柱、横梁、门将和防守球员阻挡。终结、远射、头球、任意球等能力分别参与相应计算，不仅是一个总评决定所有射门。

## 6. 防守与对抗

普通抢断动作约 0.50 秒；原地铲约 0.78 秒，跑动滑铲约 1.05 秒。滑铲距离取决于进入动作时的速度与后续减速，不同动作有独立姿态、触球有效窗口、恢复和体力消耗（普通约 7，铲球约 13）。同一铲球键按速度选择类型。

抢断要满足方向、距离、球高和动作时机。可以先碰球、先碰人、扑空、被护球阻挡或犯规；护球与身体对抗使用力量和有界体型稳定性。碰撞可造成失衡、踉跄及掉球。

防守还包括贴身慢步 / 压迫、队友协防、定向切人、封线和防守战术。高侵略性主要提高压迫意愿，不直接等同更高跑速；纪律影响 AI 危险下脚的取舍，不是一个直接抽牌概率。

## 7. 门将

门将计算球路、门线威胁、射门角度与可达时间，扩大合理控制范围，但仍受真实移动和身体范围限制。预测约向前 1.6 秒，并考虑加速；对方更容易先到时不会无条件冲出门线。

默认低地滚球以脚接球，可选择方向传给队友。手接需处于己方区域并满足高球 / 射门 / 出击 / 门线威胁条件；队友最后触球会限制手接。可手动按住门将出击，松开回到正常职责。

动画包括低扑、高扑、侧扑、捞球、脚挡、扑挡、托球、高球摘接及近距离封堵。是否抱住或扑出与球速、落点、门将能力和动作相关，不是所有接触都吸附到手上。来源：[goalkeeper_ai.gd](../space-football-demo/goalkeeper_ai.gd)。

## 8. 足球物理、碰撞与入网

球的平面状态用 Vector2 保存，另有高度和竖直速度；渲染映射到 Godot 三维空间，竖直轴为 Y。因此球确实能离地，不能把“二维战术位置”误认为“没有空中球”。

| 参数 / 过程 | 当前含义 |
| --- | --- |
| 半径 / 贴地高度 | 约 0.30 / 0.31 游戏单位 |
| 重力 | 14 游戏单位 / 秒² |
| 空中 | 旋转逐步弯曲方向、阻力衰减速度；旋转不凭空增加能量 |
| 地面 | 射门 / 传球使用不同摩擦标定；落地竖直速度约保留 32%、水平约 90% |
| 人体 | 扫掠接触结合脚、躯干、头和跳跃高度，不是全高实心墙 |
| 门框 | 连续检测门柱和横梁，降低高速穿透 |
| 进球 | 整个足球越过门线、位于门洞并低于横梁，才记分 |
| 球网 | 进球后保留球速，碰后网 / 侧网 / 顶网并衰减，网格有局部形变 |

多人碰球的被动接触设计为损耗，不再通过每个接触重复注入固定速度。物理预测用于门将、AI 和呈现，但权威判罚由比赛模拟决定。来源：[ball_physics.gd](../space-football-demo/ball_physics.gd)、[player_collision.gd](../space-football-demo/player_collision.gd)、[goal_frame.gd](../space-football-demo/goal_frame.gd)、[goal_net.gd](../space-football-demo/goal_net.gd)。

## 9. 小场规则与死球

当前采用适合产品的六人制组合规则，没有越位。规则来源与选择理由保留在 [六人制专项](SIX_A_SIDE_AND_ROADMAP.md)，不要宣称完整等同某一官方赛事。

| 情况 | 处理 |
| --- | --- |
| 边线出界 | 脚踢边线球，不是十一人制手抛球 |
| 底线出界 | 根据最后触球方判角球或球门球；冰球模式边界通常直接反弹 |
| 普通犯规 | 任意球；禁区内符合条件判点球 |
| 间接任意球 | 特定违规；禁区 / 球门区位置按规则调整 |
| 有利 | 非滑铲情形可短暂继续约 1.4 秒，失去优势可召回原犯规点 |
| 黄红牌 | 滑铲犯规可黄牌；危险背后高速铲球可直接红牌，两黄转红 |
| 红牌减员 | 120 秒有效比赛时间；少打的一方丢球可提前结束减员等待，之后按允许流程补人，原被罚者不能回场 |
| 最低人数 | 一队不足 4 名有效球员结束比赛；门将被罚有专门替补门将处理 |
| 直接进球 | 边线球、球门球、间接任意球未经他人触球直接入对方球门不算进球，改对方球门球 |
| 直接乌龙 | 重启球未经其他触球直接进本方球门，按角球处理 |

任意球防守退距为 5 米换算后的 7.25 游戏单位；本方球门线两柱之间存在例外，防守方己方任意球还约束对方退出区域。其他重启球的普通散开距离约 5.2 游戏单位，不应将二者混写为“都等于 5 米”。

设置中的“室内附加规则”默认关闭，对下一场比赛生效。开启后增加任意球 4 秒、门将后场持球 4 秒、重复回传限制和第六次累计犯规等规则；累计犯规有特殊罚球流程。

**计时细节：** 基础代码已对边线球、角球、球门球应用准备完成后的 4 秒限制；普通任意球默认约 8 秒后自动执行，开启附加规则时按 4 秒违例处理；开球、点球及累计犯规罚球保留约 8 秒自动执行。AI 通常准备约 1 秒后执行。超时边线球换对方边线球，角球变对方球门球，其他情况进入相应间接球处理。计时从准备完成开始，不把捡球路程算入四秒。

### 连续准备与跳过

死球依次经过跑去取球、抬球、带到罚球点、放球、队形组织和准备发球。过场行进速度约正常目标速度的 1.65 倍；抬球 / 放球各约 0.55 秒。这是过场节奏，不是 AI 比赛中速度加成。

长按传球约 0.85 秒出现环形进度并跳过，使用约 0.44 秒淡入淡出承接必要的位置整理。正常流程不再以悬浮大弹窗和无说明瞬移代替跑动；主动跳过仍可能在遮罩期间整理位置。按住跳过后的松开不会再误发一脚球。来源：[match_rules.gd](../space-football-demo/match_rules.gd)、[restart_flow.gd](../space-football-demo/restart_flow.gd)、[hold_skip_prompt.gd](../space-football-demo/hold_skip_prompt.gd)。

## 10. AI 跑位与球员风格

队伍先根据控球 / 防守 / 自由球阶段分配工作，再让个体移动。进攻强调接应三角、横向宽度、前插与拖后保护；防守分配压迫、拦截、盯人和保护，不让所有人同时冲向球。自由球阶段选择合适追球者；冰球墙边另外放宽可达范围。

决策评估距离、朝向、加速、转身、传球线路、高度和对手可达性。反应存在延迟，基础约 `0.16 + (1 - decisions) × 0.18` 秒，背后事件再加延迟；不是读取玩家未来按键。AI 根据压力选择传球、长传、推进或射门。

创造者偏传球 / 视野 / 决断，跑动型偏无球 / 速度 / 加速，防守型偏盯人 / 站位 / 抢断，技术型偏盘带 / 灵活，力量型偏力量 / 头球。位置进一步影响宽度与职责。三档战术改变进攻和防守取舍，能力既影响玩家手感，也影响未操控队友的行为。来源：[team_ai.gd](../space-football-demo/team_ai.gd)、[player_style.gd](../space-football-demo/player_style.gd)。
